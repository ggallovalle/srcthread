# v0.2.0 — Release tooling and Android version label

Smoother cutting of tagged builds, and the Android hello screen shows
the app version. PC install via packslip is unchanged aside from
pointing at `0.2.0`.

## Added

- **`scripts/bump-version.py`.** Bump the lockstep product version in
  one step (`X.Y.Z` or `patch` / `minor` / `major`). Updates
  `[workspace.package] version` and Android `versionName` /
  `versionCode`.

  ```sh
  scripts/bump-version.py minor
  ```

- **Android version label.** The hello screen shows
  `srcthread <versionName>` above the greeting so a sideloaded APK is
  easy to identify.

- **Required release notes file.** Publish reads
  `release-notes/<version>.md` for `gh release create` and refuses to
  run without a non-empty file. Start from
  `release-notes/TEMPLATE.md`.

## Changed

- **Workspace crate versions.** Member crates inherit
  `version.workspace = true` from the root `Cargo.toml`.

- **Publish requires an exported `PACKSLIP_KEY`.** Real and dry-run
  publishes fail if the key is missing or not a file. Dry-run still
  runs `packslip create` locally so signing is checked before tagging.

- **Android `versionName` aligned to the workspace.** Was `0.0.1`; now
  tracks the same semver as the PC build (`0.2.0`, `versionCode` 200).

## Install

PC via packslip:

```toml
[tools]
"packslip:github.com/ggallovalle/srcthread" = {
  version = "0.2.0",
  variant = "desktop",
}
```

Android: download `srcthread-0.2.0-android.apk` from this release.
