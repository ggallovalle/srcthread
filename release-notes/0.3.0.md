# v0.3.0 — Store CLI, multi-instance Android, mise release tasks

The PC spine is the in-process library (daemon dropped). CLI can init and
mutate stores on disk; Android can run several independent engines in one
session. Release tooling lives under `mise/tasks`.

## Added

- **File-store API and CLI.** Open a store, list threads, emit JSON schemas;
  load anchors, excerpts, and refs from disk; mutate with slug+ULID ids.
  CLI verbs: `store` init/list/use/lint, `thread` new/edit/rm, plus
  `anchor` / `excerpt` / `ref`, `search`, `doctor`, and thin `git` sync.

- **Multi-instance UniFFI / Android.** `SrcthreadFfi` is a per-handle object
  (no process-wide `OnceLock`). Kotlin `SrcThreadFfi` owns the handle and
  disposes on leave. The Android UI starts with several engines and can
  add/remove them; vertical list with chip-style thread rows.

- **Debug Android package.** Side-by-side `-dev` applicationId so debug
  installs do not replace the release app. `android-start` is a mise task
  and supports `--force` for version downgrades.

- **Mise file tasks for release.** Bump, render usage, tarball, checksums,
  and publish under `mise/tasks` (replacing `scripts/`). Packslip stays
  keyless via `packslip-sign.yml` after the GitHub release exists.

## Changed

- **No PC daemon.** Clients call the `srcthread` crate in-process; the
  daemon socket path is gone from the product surface.

- **CI skips detekt** when `CI=true` (or without a usable Android SDK), so
  GitHub Actions does not need a full SDK for style checks.

- **Workspace version** `0.3.0` / Android `versionCode` 300.

## Install

PC via packslip:

```toml
[tools]
"packslip:github.com/ggallovalle/srcthread" = {
  version = "0.3.0",
  variant = "desktop",
}
```

Optional postinstall:

```toml
postinstall = "srcthread integration install cursor --user && srcthread desktop install-xdg"
```

Android: download `srcthread-0.3.0-android.apk` from this release.
